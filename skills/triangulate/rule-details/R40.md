# R40 — Cross-boundary serialization shape vs strict consumer

This file contains the full normative procedure for `R40`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R40 | Cross-boundary serialization shape vs strict consumer | When one side serializes a payload consumed by another side that strictly validates or decodes it (strict schema with required fields, typed decoder, `additionalProperties:false`-style rejection), the producer's wire shape MUST match the consumer's contract exactly — field presence, type, optionality (a field omitted when null vs. sent as explicit null), enum spelling, and number-vs-string. The dangerous case is **same team owns both sides**: no external integration boundary forces a round-trip, and unit tests that mock either side pass vacuously, so the divergence (client sends `String?` always-omitted where server requires nonnegative int; client sends `[String]` where decoder expects `[{name,color}]`) only surfaces at runtime as a 400 / decode-throw / silently-dropped field — often **data-destructive** and frequently *systemic* across many fields of the same payload. Second-order: a strict-reject paired with a retry loop burns rate limiters / quotas. **Reviewer action**: for every new or changed serialized payload that crosses a process / network / storage boundary into a strict consumer, require a round-trip test that feeds *actual producer output* through the *actual consumer schema/decoder* — not two independently-mocked shapes. See Extended obligations. **Intra-language strict-decoder sub-clause**: R40 covers same-language boundaries too, not only network/web wire formats. A typed decoder in any language that declares a non-optional field (a generated-from-schema model, a typed deserializer, a strict record type) will throw or crash when the producer omits that key for an absent/null value — and because the producer and the strict consumer are both owned by the same team and each unit-mocks the other's shape, the mismatch passes vacuously until a real payload that omits the field arrives at runtime. Treat "non-optional field vs producer-omits-when-null" as the same Critical trap as the cross-process case; the fix is to align optionality (make the decoder field optional or guarantee the producer always emits it) and add the same actual-output-through-actual-decoder round-trip test. | Critical (silent total-path failure or data loss) |
