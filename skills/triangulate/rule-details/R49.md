# R49 — Undeclared control class, or a claim stronger than the implementation

This file contains the full normative procedure for `R49`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R49 | Undeclared control class, or a claim stronger than the implementation | Fires for every newly added or materially changed guard/gate/check, and for every claim made about one in a comment, doc, commit message, PR body, or Resolution Status entry. **(1) Declare the class before implementing it**, in the plan contract and at the artifact: (a) *enforceable boundary* — the actor it constrains structurally cannot bypass it; (b) *fail-closed verification gate* — bypassable by editing the gate itself, but it cannot pass without deciding, and every unresolved, errored, or absent-subject case denies; (c) *best-effort tripwire* — a heuristic over an input space that cannot be decided completely (arbitrary shell commands, natural-language content, an open-ended notation), where known bypasses exist and MUST be listed and the real recovery path (reinstall, restore, audit) MUST be named; (d) *detection or audit only* — no denial at all. Choosing (c) or (d) is legitimate; leaving the class unchosen is not, because every reader defaults to (a). A control implemented as (c) and documented as (a) is worse than no control: it moves effort off the boundary that would have worked. **(2) Calibrate every claim to what has been proven.** "Closes the class", "covers all syntaxes", "no bypass remains" require the closure argument on record — delegation to the authoritative interpreter (R47), a whitelist of the single legitimate shape, or derivation from the defining grammar or primitive (R42). Passing mutation tests over known cases proves that THOSE attacks are rejected; it is evidence about the sampled points and never about the unsampled remainder of the class (the sampling is the point: a class is closed by an argument, not by a count of green cases). Absent a closure argument the accurate wording is "rejects the known bypass shapes", with the enumeration of what is known adjacent to the claim. **Reviewer action**: for each guard in the diff, find its class declaration; for each superlative attached to a control in prose, find the closure argument or downgrade the wording. Both omissions are findings, and the second is reported even when the code is correct — the overstatement is the defect. **Distinct from**: R41 (a declared capability with no backing path at all; R49 covers a real control described as stronger than it is), R29 (accuracy of an external citation). | Major; Critical when the overstated control is relied on elsewhere as a boundary — another control was skipped, narrowed, or deferred because this one was believed to close the class |
