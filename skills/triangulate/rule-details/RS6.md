# RS6 — Incomplete sanitization — escape-character ordering

This file contains the full normative procedure for `RS6`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| RS6 | Incomplete sanitization — escape-character ordering | A function that escapes multiple characters by sequential replacement MUST escape the escape character *itself* (the backslash, or whatever the target syntax uses to introduce escapes) **first**, before any replacement that *inserts* that escape character. Otherwise a later `.replace()` inserts escape sequences that an already-run backslash pass would have neutralized, and adversarial input carrying a literal backslash survives as an unintended escaped sequence. Classic shape (Markdown-cell / CSV / shell escaping): `value.replace(/\|/g, "\\|")` with no prior `value.replace(/\\/g, "\\\\")` — input `\|` becomes `\\|` (a literal backslash followed by an escaped pipe) instead of the intended `\\\|`, letting a crafted cell break out of the table column or inject a delimiter. **Rule**: escape the escape char first, then the syntax metacharacters; equivalently, use a single-pass replacement with a character-class + callback rather than chained `.replace()`. This is CodeQL's `js/incomplete-sanitization` (High) and its cross-language equivalents. **Why the reviewer must catch it manually**: it passes eslint, tsc, unit tests, and framework build — it surfaces **only in the CI-only static-analysis job (CodeQL / Semgrep / SonarQube)**, so the first signal is a failed push round unless a reviewer reads the escape function's ordering directly. **Reviewer action**: for every sanitizer with chained `.replace()` calls, confirm the escape-introducing character is escaped by the first pass; flag any chain where a later pass inserts a character the earlier passes would have escaped. **Mechanical detection (advisory)**: grep diff `+` lines for chained `.replace(` on the same value where a later replacement's output literal contains a backslash but no earlier replacement targets the backslash — high false-positive, treat as a review prompt. | Major (Critical when the unsanitized output crosses into an interpolation/injection sink — SQL, shell, HTML attribute, template) |
