# R50 — Verification preconditions unverified (success inferred from a proxy signal)

This file contains the full normative procedure for `R50`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R50 | Verification preconditions unverified (success inferred from a proxy signal) | Fires whenever a verdict is drawn from a verification run — a build, type-check, test suite, analyzer, gate, or self-test. The count of passing cases and the presence of an output artifact are proxies, not the verdict; six preconditions decide whether the run means anything, and each is checked BEFORE the result is quoted. (i) **Exit status**: the tool exited 0 — never infer success from an emitted artifact, because a compiler or generator that reported errors still emits partial output, and "the declaration file exists" then reads as "the program is well-formed" (pairs with R44, which covers the same verdict being lost in the channel it is read through — R50 covers the run itself). (ii) **Input resolution**: every input the tool needed actually resolved; unresolved imports, missing dependencies, or a glob that matched nothing silently shrink the analyzed set, and a gate over an empty set passes. This clause is an *assertion*, not a caution — "looked at nothing" and "found nothing wrong" are the same exit status, so the gate must emit positive evidence that it examined the intended subjects: a non-zero analysed-subject count; a coverage floor tight enough that dropping any real subtree breaches it (a bare "≥ N subjects" floor is satisfiable by N while every new one goes uncollected); a named representative per scan branch; and, where the tool resolves per-subject configuration, an assertion on the *resolved rule set* for that representative, since appearing in the report does not mean any rule applied to it. Absence or unparseability of a derived input is a distinct non-zero exit, never a fallback and never a per-check `if input exists` guard — that guard inverts the fail direction, reporting clean when the input is deleted and drift when it is corrupted; required inputs belong in a preflight that fails hard. Any scope-affecting override — a test seam reparameterizing the scan root, an ignore list, an environment variable — must be asserted unset in the authoritative run, because a deliberately emptied scope is indistinguishable at runtime from a misconfiguration that emptied it. (iii) **Subject identity**: the artifact analyzed is the one that ships — same program, entry set, and config as production, not a test-only reconstruction (pairs with RT5 and RT9). (iv) **Toolchain pinning**: the tool is invoked at a pinned version through a resolver that cannot silently select or fetch a different one; a gate run through an auto-fetching launcher decides with a tool nobody reviewed, and its verdict is not reproducible. Unavailability of the pinned tool must deny, never fall back to whatever is present. (v) **Run isolation**: the run does not mutate the tracked worktree or any state shared with concurrently running jobs — a self-test that edits the source it checks races the build and lint beside it, corrupting both the verdict and the tree; work on a scratch copy and verify restoration (pairs with the R21 destructive-verification carve-out). (vi) **Reviewability of the gate itself**: the gate's own source must stay readable in the tools the project reviews with — literal control bytes (NUL and friends) in a tracked file make it binary to VCS diff and PR views, so subsequent edits to the gate ship unreviewed; keep byte-level framing at runtime (constructed in-process, or written in an escaped textual form) rather than as raw control bytes in tracked source. **Reviewer action**: for each verification cited as evidence in the round, quote the exit status and the analyzed-subject identity alongside the pass count; a cited pass count with neither is the finding. | Major; Critical when the unverified precondition means a security gate never actually ran, ran on the wrong subject, or reported green from a failed toolchain |
