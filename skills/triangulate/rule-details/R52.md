# R52 — Control reach extended without re-auditing the control itself

This file contains the full normative procedure for `R52`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R52 | Control reach extended without re-auditing the control itself | Fires when a change increases the set of paths, principals, requests, or records that an EXISTING control decides — collapsing two adjudicators into the stronger one (R48), retrofitting a guard across a newly derived member set (R42), removing a pre-filter, promoting an opt-in check to the default. Such a change is reviewed as a *coverage* change, so the whole budget goes to "does every path now reach the control" and the control's own correctness reads as settled because it already shipped. It is not: the change multiplies the blast radius of every latent defect inside the control and everything it calls, including defects whose current symptom is too narrow for anyone to have reported. The recurring shape is a parse/lookup helper that mis-handles a configured value the old, narrower population never produced — before the change it denies a thin slice of requests, after it the same defect denies an entire tenant, and because the widened control is fail-closed the symptom is a total outage rather than a finding. **Do**: treat the control and every helper on its decision path as in scope for a fresh correctness audit against the NEWLY covered population — enumerate the input shapes and configured values that population can produce and the old one could not — R48's strict-direction sub-clause already lists the shapes worth walking — and check each against the HELPER rather than against the control's own predicate. Where the audit surfaces a prerequisite ("fix X before shipping Y"), it becomes a field in the artifact that GATES completion — a dependency column in the acceptance table — never a note in prose beside it, because prose does not block a merge. State where the newly-strict control's recovery path lives and prove by test that the recovery path does not itself traverse the dependency that fails closed. **Distinct from**: R48's strict-direction sub-clause — the nearest neighbour, and the one to check first: R48 fires when the surviving adjudicator is STRICTER than what the primary path legitimately produces, so the fix is to pin it "never stricter"; R52 fires on a latent defect in the survivor's own helper chain, which is not a strictness question and is not fixed by pinning. A collapse of two adjudicators fires both, and discharging one does not discharge the other. Also R43 (the boundary gets more permissive; R52 is the boundary getting stricter while the control's *population* grows), R42 (which members the control must cover; R52 is the control's own correctness once it covers them), R34 (whether a known adjacent bug may be deferred; R52 is what promotes a latent one from unreported to Critical), R3 (propagation, which here was complete — the propagated thing was defective). | Major; Critical when the widened control is fail-closed and the latent defect denies a whole class of principals rather than a single request |
