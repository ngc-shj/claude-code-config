# R34 — Pre-existing bug in adjacent file deferred without Anti-Deferral cost-justification

This file contains the full normative procedure for `R34`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R34 | Pre-existing bug in adjacent file deferred without Anti-Deferral cost-justification | Cross-references the existing **Anti-Deferral Rules** section above; do not restate the 30-minute rule or the Worst case / Likelihood / Cost-to-fix triple. R34's unique contribution: when implementing a change, the reviewer MUST enumerate sibling files in the same directory or imports of the same module and scan for the SAME class of bug being fixed in the diff. If a sibling exhibits the same pattern AND has not been fixed in this PR AND no Anti-Deferral cost-justification is filed, R34 fires Major. **Security carve-out** (closed list, aligned with R35 Tier-2): when the adjacent bug touches auth flows, authorization changes, cryptographic-material handling, session lifecycle, identity-broker/federation trust, key custody, zero-trust/service-mesh policy, webhook signing-key rotation, secrets handling, audit logging, rate-limiting / authentication-failure paths, or input validation, R34 inherits the Anti-Deferral security carve-out — impact analysis (R3 propagation trace) is required before deferring, regardless of estimated cost. **Invariant**: if R35 Tier-2 grows in a future PR, this closed list MUST grow in lockstep. **The filed justification is a review subject, not a review input (mined extension)**: a deferral entry that CARRIES a Worst-case / Likelihood / Cost triple is still in class when any part of the triple is falsifiable, because the author who decided to defer also wrote all four estimates — worst case, likelihood, cost, and the mechanism's own framing — each biased toward the decision already made. Observed understatements, all correct when re-derived: an entry naming one sink where the code has three and rating the item Minor; an entry rating a hand-edit typo "likelihood low" while mis-stating the abort scope (it aborts the source, where the consumer aborts the run) and asserting an assertion existed that did not; an entry framing a gap as a cardinality problem when the artifact under test was unasserted entirely, at any cardinality. Verify the sink enumeration against the code, the blast scope against the CONSUMER rather than the producer, and the stated mechanism against execution; raise the finding at its true severity, not the recorded one. A justification that ENUMERATES the exposed member set must state it as a derivation rather than a list and re-derive it at close-out — a justification that was true when written and is falsified by a later round of the same change is the same defect as never writing one. **Structural bar (not a severity question)**: a deferral is disallowed outright, regardless of the remedy's size or the cost triple, when the deferred class member sits on the IN-SCOPE remedy's trigger or observability path — deferring it removes the ability to detect that the in-scope remedy works at all (observed: a future value in the deferred sibling makes the source never become due, so the in-scope component is never invoked and its own announcement is unreachable). A deferral justified on reachability must additionally be re-adjudicated when the same change alters that reachability. Finally, distinguish "deferred, cost-justified" from "not done, ran out of time": the latter is a completeness gap reported as such, never spelled as a decision | Major |
