# R2 — Constants hardcoded in multiple places

This file contains the full normative procedure for `R2`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R2 | Constants hardcoded in multiple places | Search for literal values that should be shared constants (validation limits, enum values, config defaults). **Mechanical detection**: `bash ~/.claude/hooks/check-hardcoded-reuse.sh [base-ref]` indexes module-level `const NAME = literal` declarations across unchanged source files (TS/JS / Python / Go) and cross-references diff `+` lines for hardcoded values that match an existing single-candidate constant. String matches → Major (precise); numeric matches → Minor (small numbers collide across protocol byte codes / array indices, treat as advisory). The hook sees only diff `+` lines — preventive R2 surfacing for the whole codebase remains the fingerprint's job (`build-codebase-fingerprint.sh`). Multi-candidate matches (one value mapped to ≥2 constants) are dropped by default; raise `MAX_CANDIDATES_PER_VALUE` to see them. **Value-equality is not meaning-equality (before replacing)**: a hardcoded literal matching an existing constant's *value* does NOT license the replacement — confirm the two share *meaning*, not just bytes. Two `3600`s can be a cache TTL and an HMAC clock-skew window; two `"active"`s can be a subscription state and a feature-flag key. Replacing one with an import of the other couples two independent concepts that will silently drift the day one of them changes — a behavior regression disguised as a cleanup. The numeric-match Minor downgrade covers the *false-positive* rate (coincidental collisions), not this *semantic* trap: even a confirmed string match must pass the "do these name the same concept?" check before the import is applied. When the values coincide but the concepts differ, the correct action is the opposite of R2 — keep them separate (optionally give each its own named constant) and note why. This is the mirror of the simplify value-handling diff audit: R2 warns against *splitting* one concept across literals; this clause warns against *merging* two concepts that happen to share a value | Major |
