# R54 — Control suspension granted through ambient context state

This file contains the full normative procedure for `R54`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R54 | Control suspension granted through ambient context state | Fires when a routine is permitted to bypass an invariant-enforcing control (append-only or immutability enforcement, row-level security, an audit trigger, a rate limiter, a foreign-key or constraint check) and the grant is expressed by SETTING AN AMBIENT FLAG inside the routine's body — a session or transaction variable, a thread-local, a request-scoped context value, a global "in maintenance" boolean. The grant's lifetime is then the enclosing context, not the operation it was granted for, so every subsequent statement in that transaction / request / thread inherits the exception. The failure needs no attacker: calling the sanctioned routine from a shared cleanup or batch helper silently disarms the control for everything that follows it in the same context. Two properties make it survive review. (1) The obvious test passes — issuing the forbidden operation in the NEXT context observes a fresh ambient state, so a leaking implementation is green. (2) An unregistered ambient variable is settable by any principal, so the "authority" is a convention rather than a boundary, and the control's class declaration (R49) reads as (a) *enforceable boundary* when the implementation is (c) *best-effort tripwire*. **Do**: scope the suspension to the CALL — a declaration on the routine that the runtime saves and restores around invocation, including on the error path — never by setting the flag and relying on the body to unset it, which the error path skips. Test the invariant in the SAME context immediately after the sanctioned call returns. Where the platform offers no call-scoped form, wrap the grant in an explicit acquire/release with the release in the language's finally-equivalent, and state in the control's class declaration that an ambient flag any principal can set bounds nothing — the real bound must be a capability the adversary does not hold. **The remaining six obligations, added because reviewers holding the three above still shipped fixes without them** (`evals/rule-ablation`, `docs/archive/audit/2026-08-04-rule-ablation.md`): (a) **restore the PREVIOUS value, never a hardcoded off/false** — a nested or already-granted outer scope is otherwise ended early by the inner release, which is the same leak inverted; (b) **await the covered work before restoring** — returning the callback's promise un-awaited lets the release run before the work it covers, and a `finally` added to that shape is decoration; (c) **do not mutate state the caller shares — name which variant applies and state its mechanism in the fix.** Context-carried flag (thread-local, request context): enter a FRESH FRAME — a nested context store — never a write to the caller's frame. Connection- or session-scoped setting (a database session variable): pin ONE HANDLE — the set, the covered work, and the restore must all run on the same connection, and the fix must say so, because a pool may hand each statement a different connection: the grant lands on one handle, the work on another, and the restore on a third, leaving a connection nobody is watching still elevated; (d) **a failed restore must abort, not continue** — swallowing it leaves the control off for the remainder with no signal, and it must not mask the callback's own error; (e) **test the throw path**, not only the return path — the release that exists solely for the error case is the one no reviewer exercises; (f) **test nesting AND concurrent use — both, not either.** NESTING: enter a second grant inside an open one, and assert the inner release did not end the outer grant. CONCURRENCY: hold the grant open while a second request, transaction, or frame runs, and assert that one is unaffected. **Concurrency is the half that must not be dropped**: nesting is already largely forced by (a), while a save/restore on state the caller shares passes the return-path test, the throw-path test AND the nesting test, and fails only under concurrent use — which is the shape (c) exists to prevent. This clause was written as a choice until 2026-08-06, and the second branch did not survive it: across sixteen blind-scored reviews carrying the rule, on both arms of a structure ablation, the nesting test appears 16/16 and the concurrency test 0/16 (`docs/archive/audit/2026-08-05-specialisation-vs-repetition.md`, round 11). An obligation offering alternatives transmits the first one. **Distinct from**: R39 (clearing secret material at a lifecycle boundary), R38 clause (2) (an interval across async suspension points inside one principal), R51 (a name re-resolved to a different object), R5/R9 (transaction scope of the guarded work, not of an exception grant). | Major; Critical when the leaked suspension covers an audit, append-only, tenancy, or authorization control, since every statement after the sanctioned call runs unguarded |
