# R56 — Progress-marker heal direction

This file contains the full normative procedure for `R56`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R56 | Progress-marker heal direction | Fires when code repairs an out-of-range persisted progress marker — a watermark, checkpoint, consumer offset, keyset cursor, incremental-backup timestamp, last-seen or high-water value. The two repair directions are NOT symmetric. Healing the marker FORWARD toward the present (clamping a future value to "now", advancing past a gap) discards every unprocessed item behind it irreversibly, because the items' own timestamps do not move with the marker; healing it BACKWARD to the floor costs a bounded re-process. The forward direction is the one that looks tidy and the one a name like *clamp* suggests, and it fails silently — a source that lost its backlog and a source that is genuinely drained emit byte-identical output on every channel. **Do**: heal in the RE-PROCESS direction only, and state the invariant so it is checkable on every branch: the healed value is ≤ the persisted value on every path, including degraded and error paths, which makes emitting the healed value unconditionally safe. Name the operation for what it does, and check that the operator-facing wording implies the correct recovery model — "clamped to now" tells an operator the opposite of what happened. Emit a diagnostic that distinguishes a healed run from an ordinary one, since the two are otherwise indistinguishable downstream. **Composition check**: a backward heal WIDENS the candidate set, so where candidates feed an off-machine path (a remote model, an upload, a notification), the healing run must disable that path or bound the widened set — the fix for a data-loss bug must not become an egress event (R43). **Distinct from**: R25 (persist/hydrate symmetry — whether the value comes back, not which way it is repaired), R38 (fail-open supersession on session state), R50 (which covers only the observability half: a blind run and a drained run reading the same). | Major; Critical when the forward heal drops items that no other system retains, or when the widened candidate set of a backward heal crosses a trust or egress boundary |
