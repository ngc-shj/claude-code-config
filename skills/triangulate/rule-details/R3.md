# R3 — Incomplete pattern propagation

This file contains the full normative procedure for `R3`. The compact row in `../common-rules.md` is only its routing summary.

## Full rule

| ID | Pattern | Procedure | Severity if missed |
|---|---|---|---|
| R3 | Incomplete pattern propagation | When a pattern is changed in one file, search for ALL other files using the same pattern. **Flagged-instance enumeration obligation**: when a user or reviewer flags a single instance of an anti-pattern, the reviewer MUST enumerate every other instance of the same anti-pattern in the same response — not only fix the flagged one. "Fix what was pointed out and nothing else" defers the other instances to the next review round and wastes rounds on avoidable repetition. **Mechanical detection**: `bash ~/.claude/hooks/check-propagation.sh [base-ref]` surfaces three categories of unpropagated changes diff-wide — symbol renames (Minor; identifier-rename detection without AST is inherently noisy, treat as advisory), constant value changes (Major; const NAME = OLD → NEW with hardcoded OLD still elsewhere), and string literal changes (Major; removed string still verbatim elsewhere). Use its output as a starting list, not a complete one — type-level renames, function signature changes, and regex/validation rule changes need manual cross-cutting verification. **Propagation is not blind copy — verify each target site's local constraints**: applying the same change to every matching site assumes every site shares the *reason* the change was correct at the seed. It often does not. Before copying the seed edit into a target, confirm the target satisfies the same preconditions the seed did — the same nullability, the same call ordering, the same value domain, the same surrounding guard. A change that is correct at site A (where a prior line already null-checks) can be a bug at site B (where it does not); a "more robust" refactor propagated from the seed can break an invisible contract a target site was quietly relying on (see Expert Agent Obligations "A more robust alternative must enumerate the current approach's implicit constraints"). R3 obligates enumerating the sites; it does not license editing each without re-reading its local context. When a target's constraints differ, that divergence is itself a finding — the sites were only *superficially* the same pattern | Critical if security-relevant, Major otherwise |
