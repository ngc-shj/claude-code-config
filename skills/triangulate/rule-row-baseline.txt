# Row-size ratchet baseline — machine-read by hooks/check-rule-sync.sh (check 9).
#
# A rule row in common-rules.md is a ROUTING SUMMARY. When the procedure is
# large it belongs in rule-details/<ID>.md, which the row points at; the ten
# rows that follow that convention measure 370-992 bytes. This file lists the
# rows that do NOT, and therefore exceed the 1200-byte ceiling.
#
# It exists because the convention was written down for a long time without
# anything measuring it, and a convention nobody measures is a wish. The linter
# enforces the ratchet in BOTH directions:
#
#   - a row over the ceiling that is absent here is drift (no silent growth)
#   - a line here whose row now fits is drift (the list can only shrink)
#   - the annotation must match the row (see below)
#
# So the way to remove a line is to move that rule's procedure into
# rule-details/<ID>.md, not to edit this file.
#
# Column 2 records whether the row names a **Mechanical detection** paragraph.
# It is the input folding.md consults before letting a repeated `Extends` land
# as still more prose: naming a class is not the same act as installing its
# inspector, and a rule that has absorbed several rounds of prose while staying
# `no-inspector` is the signature of that confusion. 30 of the 37 rows below are
# `no-inspector`, and every rule from R44 onward is — the recent folds produced
# text and no detectors.
#
# Format: <rule-id><TAB>inspector|no-inspector   (# comments and blanks ignored)
