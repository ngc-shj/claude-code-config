### Critical: the bytes that are signed are not the bytes that are sent, so no receiver can ever verify a delivery
File: app/webhooks/signing.py — `sign` / `serialize`, used by app/webhooks/delivery.py — `send_once`
What is wrong: `sign` computes the HMAC over `json.dumps(payload, sort_keys=True)` while `send_once` transmits `client.post(..., json=delivery.payload)`, which httpx serializes in insertion order with its own separators, so the signed string and the request body differ for any payload whose keys are not already sorted — the fixture payload `{"id", "type", "amount_cents"}` in tests/webhooks/test_delivery.py is exactly such a case (sorted order is `amount_cents, id, type`) — and the timestamp the docs say is part of the MAC input (`"{timestamp}.{raw_request_body}"`, docs/webhooks.md) is not fed into `hmac.new` at all.
